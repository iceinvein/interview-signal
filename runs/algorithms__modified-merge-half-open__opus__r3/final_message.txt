**How it works:**
1. It drops every interval with `start === end`, so they can never join or bridge other intervals.
2. It sorts the rest by `start`.
3. It walks through them in order. An interval joins the previous group only if its start is strictly less than the group's end (`s < last[1]`). Intervals that just touch, like `[1,3]` and `[3,5]`, stay separate.

It returns new arrays and leaves your input alone. Sorting dominates the cost, so it takes O(n log n) time, which is fine for 100,000 intervals.

**Test results:**
- `[[3,5],[1,3]]` → `[[1,3],[3,5]]` (touching intervals stay separate)
- `[[1,4],[2,2],[4,6],[5,8],[0,0]]` → `[[1,4],[4,8]]`
- `[[1,3],[3,3],[3,5]]` → `[[1,3],[3,5]]` (the empty `[3,3]` doesn't join its neighbours)
- `[[1,5],[1,5],[2,3]]` → `[[1,5]]` (duplicates and contained intervals merge)
- `[]` and `[[2,2]]` → `[]`
